# Обучение YOLO для распознавания схем

Пошаговая инструкция: от данных Максима до работающей модели на сервере.

## Что попросить у Максима

1. **Экспорт разметки**: в его Label Studio → Export → формат **JSON** (не YOLO! —
   YOLO-экспорт из LS нумерует классы по порядку меток и не совпадает с
   нумерацией `category`, которую понимает наш сервер).
2. **Папку с картинками схем** — те файлы, что он загружал в Label Studio.
3. **Актуальный конфиг разметки** (Settings → Labeling Interface → Code) — если
   менялся с прошлого раза.

Датасет из нашей системы (кнопка «Скачать датасет (ZIP)» на странице «⚡ Схемы»)
конвертации не требует — он уже в правильном формате, можно просто слить его
папки с папками Максима.

## Шаг 1. Собрать датасет

### Вариант А — Максим прислал YOLO-экспорт (папки images/ + labels/ + notes.json)

Так он присылает с конца июля. Конвертация не нужна, только склейка партий:

```bash
python tools/training/merge_yolo_export.py --out dataset "путь/к/partition_1" "путь/к/partition_2"
```

Номера классов в таком экспорте уже равны `category` из конфига разметки —
ровно то, что ждёт сервер Zeus, перенумеровывать ничего не надо. Скрипт делает
train/val split и `data.yaml` с именами классов из `notes.json`.

**Важно:** если в `notes.json` появились категории, которых нет в
`tools/training/config.xml`, добавьте их туда и обновите конфиг в системе
(«Схемы» → «Датасет» → «Обновить классы»), иначе сервер вернёт такие элементы
как «Прочее».

### Вариант Б — прислан JSON-экспорт задач Label Studio

```bash
python tools/training/convert_ls_to_yolo.py \
  --json export.json --images ./images --config config.xml --out ./dataset
```

Скрипт разложит всё в структуру ultralytics (`images/train|val`, `labels/…`,
`data.yaml`) и пронумерует классы по `category` из конфига — ровно так, как
ждёт сервер. В конце напечатает статистику и предупредит о ненайденных
картинках или метках вне конфига.

## Шаг 2. Обучить

Нужна NVIDIA-видеокарта от 6–8 ГБ (RTX 3060+) или Google Colab (бесплатного T4
хватает на такой датасет, ~30–60 минут).

```bash
pip install ultralytics
yolo detect train data=./dataset/data.yaml model=yolov8s.pt epochs=150 imgsz=1280 batch=8
```

- `model=yolov8s.pt` — старт с предобученных весов (transfer learning), с нуля не учим.
- `imgsz=1280` — символы на листах мелкие, 640 их теряет. Если видеокарта не тянет — `batch=4`.
- Датасет маленький (десятки листов) — не гнаться за yolov8m/l, начинать с n/s.
- Результат смотреть в `runs/detect/train/`: `results.png` (кривые), `confusion_matrix.png`,
  метрика mAP50 в консоли. mAP50 > 0.6 для первой версии — уже неплохо.

В Colab то же самое: загрузить `dataset.zip`, распаковать, те же две команды.

## Шаг 3. Экспортировать в ONNX

```bash
yolo export model=runs/detect/train/weights/best.pt format=onnx imgsz=1280
```

**Размер `imgsz` при экспорте должен совпадать с настройкой сервера.** Сервер
по умолчанию ждёт 640; для 1280 добавьте на сервере в
`/opt/indexall/backend/.env.production`:

```
RECOGNITION_YOLO_SIZE=1280
```

и перезапустите backend (`docker compose -f docker/docker-compose.prod.yml up -d backend`).

## Шаг 4. Загрузить на сервер

Страница «⚡ Схемы» → панель «Модель YOLO и режим распознавания»:

1. «Загрузить модель (.onnx)» — файл `best.onnx`, в заметку написать что-то вроде
   `v1 — 48 схем, mAP50=0.71`.
2. «Активировать».
3. Режим → **«Теневой (LLM + YOLO)»**: пользователи продолжают получать результат
   LLM, а YOLO меряется рядом — в панели копятся строки «LLM n рамок / YOLO m рамок».
4. Когда YOLO стабильно догоняет LLM по количеству и качеству рамок — переключить
   на **«Каскад (YOLO → LLM)»**: рамки и классы находит YOLO (быстро и бесплатно),
   параметры дочитывает LLM.

Старая версия остаётся в списке — откат в один клик («Откатиться на эту»).

## Известный нюанс качества

Максим размечает **целые листы**, а сервер распознаёт **вырезанные зоны** —
масштаб объектов на инференсе крупнее, чем на обучении. Ultralytics частично
компенсирует это аугментацией (scale), но если в теневом режиме YOLO будет
стабильно мазать — следующий шаг: при обучении нарезать листы на тайлы
(например 4×4 с перекрытием) или собирать датасет из наших же зон
(ZIP из системы содержит именно страницы — при активном использовании модуля
он быстро станет основным источником).
